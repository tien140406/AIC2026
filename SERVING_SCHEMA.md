# Query Serving: Elasticsearch and Milvus

Generated Parquet/JSON/NumPy artifacts under `workspace/` remain the source of
truth. The serving layer is rebuilt from those artifacts:

```text
final keyframes + OCR + object metadata ---> Elasticsearch: aic-frames-v1
ASR L0/L1 segments -----------------------> Elasticsearch: aic-asr-segments-v1
OpenCLIP keyframe vectors ----------------> Milvus: keyframe collection
OpenCLIP object ROI vectors --------------> Milvus: ROI collection

text query -> OpenCLIP text vector -> Milvus
text query ------------------------> Elasticsearch
                                      |
                                      v
                         frame-level RRF fusion
```

The old SQLite catalog is retained for local debugging and compatibility. The
Elasticsearch/Milvus production path does not depend on it.

## Production-like local stack

The repository provides a Docker Compose stack matching the production data
split: Elasticsearch stores OCR, object metadata, and ASR; Milvus standalone
stores OpenCLIP keyframe and ROI vectors. Milvus uses local etcd and MinIO
services for metadata and object storage.

```bash
docker compose -f environments/serving/docker-compose.local.yml up -d
docker compose -f environments/serving/docker-compose.local.yml ps
```

Local endpoints:

```text
Elasticsearch  http://localhost:9200
Milvus         http://localhost:19530
Milvus health  http://localhost:9091/healthz
MinIO API      http://localhost:9000
MinIO console  http://localhost:9001
```

After every service reports healthy, verify connectivity plus temporary
write/search/delete operations in both databases:

```bash
uv run --project environments/serving \
  python scripts/check_local_serving.py --smoke-write
```

Stop the stack without deleting its named volumes:

```bash
docker compose -f environments/serving/docker-compose.local.yml down
```

The next `up -d` reuses the existing data. Avoid `down -v` unless the intent is
to permanently remove all data in this local serving stack.

## Stable identity

```text
frame_uid = <video_id>:<zero-padded-original-frame_id>
roi_uid   = <frame_uid>:roi:<detector-run-hash>:<detection_id>
segment_id is generated by the ASR pipeline
pts_ms    = integer presentation timestamp in milliseconds
```

Milvus ROI records carry `parent_frame_uid`. Elasticsearch ASR records carry
`keyframe_uids`. Both can therefore collapse back to the same final keyframe.

`embedding_row` is only an offset inside one local matrix file; it is never an
external ID.

## Elasticsearch

Defaults:

```text
URL         http://localhost:9200
frame index aic-frames-v1
ASR index   aic-asr-segments-v1
```

Configure the endpoint through CLI flags or:

```bash
export ELASTICSEARCH_URL=http://localhost:9200
export ELASTICSEARCH_API_KEY=
export ELASTICSEARCH_USERNAME=
export ELASTICSEARCH_PASSWORD=
export ELASTICSEARCH_FRAME_INDEX=aic-frames-v1
export ELASTICSEARCH_ASR_INDEX=aic-asr-segments-v1
```

### Frame documents

There is one `aic-frames-v1` document per final keyframe, keyed by `frame_uid`.
It contains:

```text
frame_uid, video_id, frame_id, shot_id, pts_ms
image_path, image_sha256
selection_encoder_id, selection_version
ocr_text
ocr[] -> stage/model/version/status/text/blocks
object_classes, object_text
objects[] -> model/run/detections(label, bbox, score, area)
```

OCR and object arrays use nested mappings. Text fields use a lowercase analyzer
with ASCII folding while preserving the original Vietnamese tokens.

### ASR documents

There is one `aic-asr-segments-v1` document per L0/L1 segment, keyed by
`segment_id`:

```text
segment_id, video_id, level
start_ms, end_ms
raw_text, clean_text, language, provider, model
shot_ids, primary_shot
keyframe_ids, keyframe_uids
confidence, quality_score, source_manifest
```

ASR stays segment-level. It is not duplicated as one document per keyframe.

### Build and query

Indexing uses deterministic document IDs, so rerunning the command upserts the
same documents. Use `--recreate` for a clean rebuild when artifacts were
removed or schemas changed.

```bash
uv run --project environments/serving \
  python scripts/index_elasticsearch.py \
  --selection-encoder-id timm_beit3_base_patch16_224_pt \
  --recreate

uv run --project environments/serving \
  python scripts/query_elasticsearch.py \
  --query 'ca chua person' \
  --limit 20
```

## OpenCLIP ROI embeddings

Object metadata must be filtered before ROI embedding. The ROI extractor reads
`detections.parquet` and the immutable final-keyframe JPG manifest, expands each
box by 5% by default, crops in memory, and uses the same OpenCLIP model as the
full-frame retrieval embeddings.

```bash
uv run --project environments/beit3-timm \
  python scripts/openclip_roi_embeddings.py \
  --video-id L21_V001 \
  --model-id co_dino_5scale_lsj_r50_3x_coco \
  --padding-ratio 0.05
```

Outputs:

```text
workspace/features/openclip_vit_b16_laion2b_s34b_b88k_roi/
  <video_id>.f16.npy
  <video_id>.parquet
```

The mapping stores `roi_uid`, `parent_frame_uid`, detector provenance, class,
confidence, original normalized bbox, expanded crop bbox, and embedding row.

## Milvus

Use one collection per entity/model/version:

```text
keyframe_<openclip_model>_<version>
roi_<openclip_model>_<version>
```

Keyframe scalar fields:

```text
frame_uid (primary), video_id, frame_id, shot_id, pts_ms, image_path
```

ROI scalar fields:

```text
roi_uid (primary), parent_frame_uid
video_id, frame_id, shot_id, pts_ms
class_id, class_name, confidence
x_min_1000, y_min_1000, x_max_1000, y_max_1000
```

Both collections use a normalized float vector with cosine `AUTOINDEX`.

Ingest directly from feature artifacts:

```bash
uv run --project environments/serving \
  python scripts/ingest_milvus_artifacts.py \
  --entity-type keyframe \
  --encoder-id openclip_vit_b16_laion2b_s34b_b88k

uv run --project environments/serving \
  python scripts/ingest_milvus_artifacts.py \
  --entity-type roi \
  --encoder-id openclip_vit_b16_laion2b_s34b_b88k_roi
```

Use `--drop-existing` when intentionally rebuilding a collection.

## Hybrid retrieval

`run_query_pipeline.py` orchestrates backend startup/health checks and then calls
`query_hybrid.py`:

1. encodes the query with the matching OpenCLIP text tower;
2. searches keyframe and ROI Milvus collections;
3. searches OCR/object frame documents and ASR segment documents;
4. maps ROI hits through `parent_frame_uid`;
5. maps ASR hits through `keyframe_uids`;
6. combines ranks with Reciprocal Rank Fusion;
7. returns one result per `frame_uid` with evidence from each source.

```bash
python3 scripts/run_query_pipeline.py \
  --query 'nguoi cam ro ca chua' \
  --candidate-limit 100 \
  --limit 20
```

Use `--no-start-serving --no-check-serving` when Elasticsearch and Milvus are
already managed outside this repository.

Every orchestrated query writes a JSON execution/result report, an HTML report
with visible keyframe thumbnails, and a sibling `query_assets_<timestamp>/`
directory containing copies of the returned JPGs under `workspace/reports/`.

Cosine and BM25 scores are included as evidence but are not added directly;
RRF combines ranks because the score distributions are not comparable.

## SQLite compatibility

The existing SQLite catalog and transcript FTS5 commands remain available for
local tests and debugging:

```bash
uv run --project environments/serving \
  python scripts/build_serving_catalog.py

uv run --project environments/serving \
  python scripts/query_serving_catalog.py \
  --frame-uid L21_V001:000000120
```

They are not required by `index_elasticsearch.py` or
`ingest_milvus_artifacts.py`.
